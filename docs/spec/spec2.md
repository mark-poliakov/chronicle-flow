# Завдання 2 — Робочий застосунок: прототип → інтеграція з БД

## Намір

Реалізувати прототип застосунку, який включатиме готові фронтенд та бекенд і їхню взаємодію. Всі базові дії з щоденником (створення, редагування, видалення і власне перегляд записів) мають бути реалізовані. Додати простеньку реєстрацію та вхід. Виконати обов'язкові вимоги завдання. Виконати зауваження першої перевірки.

Сценарії з очікуваною поведінкою: `/docs/architecture/data-flows.md`

Контракт API + запити: `/docs/architecture/api.md`

Схема БД: `/docs/architecture/data-model.md`

## Out of scope

_Коментар: деякі документи все ще містять старі версії специфікації застосунку, хоча явні невідповідності прибрано (PostgreSQL в технічному стеці, RevisionType поле, від якого відмовились). Після злиття гілки 'chore/add-format-lint-build-precommit' очікується, що все буде ідеально. Наразі прохання не звертати на інші, не загадні у першому відгуці, невідповідності або помилки._

Поза межами цієї роботи є:

- відмальовування гарної шкали часу
- кастомний гарний календар із відображенням днів, за які є записи
- будь-яке розгортання
- реалізація просунутих паттернів, таких як: health check, retries pagination, та інші, про існування яких я, може (скоріш за все), навіть і не здогадуюсь, і які не дуже доречні в невеликому проекті
- UserModule - відповідно, керування профілем є поза межами цієї роботи
- топ-тир документація API (наприклад, за допомогою Swagger), точний опис сигнатур headers та body, відповідей
- покриття 100% можливих сценаріїв збоїв (сюди входить обробка недоступності Prisma)

## Критерії прийняття

- Готовий фронтенд, на якому наявні всі необзідні кнопки і форми для базових операцій
- Реалізована реєстрація та вхід
- Готовий бекенд, який відзеркалює наявні операції на фронтенді (хоча, мабуть, правильніше казати навпаки)
- Задокументовано API, можна доволі поверхнево: API шлях і словесно що приймає і що повертає
- Є рівні декомпозиції на бекенді: роути, сервіси, репозиторії
- Реалізовано логування із Business Process ID (requestId)
- Є мінімальна обробка помилок
