##Сутність 1: User (Користувач)
Зберігає дані про власника щоденника.

- id (UUID, Primary Key)
- email (String, унікальний)
- passwordHash (String)
- createdAt (Timestamp)

##Сутність 2: Entry (Контейнер дня)
Ця сутність означає не просто «текст», а сам факт наявності запису за конкретну календарну дату. Тобто це «обкладинка» дня в щоденнику.

- id (UUID, Primary Key)
- userId (UUID, Foreign Key -> User.id) — кому належить запис.
- targetDate (Date) — календарна дата, до якої належить запис (наприклад, 2026-10-10). Важливо: це не дата створення в базі, це день, про який пише користувач.
- createdAt (Timestamp) — коли вперше був створений контейнер цього дня.

##Сутність 3: EntryRevision (Історія версій та доповнень)
Ось тут зберігається сам текст. Кожного разу, коли користувач створює запис або робить ретроспективну правку (навіть через тиждень), ми не перезаписуємо старий текст, а створюємо новий рядок-ревізію.

- id (UUID, Primary Key)
- entryId (UUID, Foreign Key -> Entry.id) — до якого дня прив'язаний цей текст.
- content (Text) — сам текст або вміст запису.
- revisionType (Enum: INITIAL або RETROSPECTIVE_EDIT) — метадані про те, чи це був оригінальний запис, чи пізніше доповнення.
- createdAt (Timestamp) — точна мітка часу (година, хвилина, дата), коли саме користувач написав або відредагував цей текст.

##Зв'язки між таблицями:

User (1 до багатьох) Entry: у одного користувача багато записів за різні дні.

Entry (1 до багатьох) EntryRevision: у кожного дня є один або кілька текстових шарів/версій через правки.
